# 설계 스펙: Check Kopilot — 트레이더용 자연어 CHECK API 코파일럿

> 구현 계획: [plan.md](plan.md) · CHECK API 조사: [check-api/README.md](check-api/README.md) · 문서 인덱스: [README.md](README.md)

- 작성일: 2026-07-18
- 상태: 사용자 승인된 설계 (구현 계획 수립 전)
- 맥락: 코스콤 미니프로젝트(해커톤), 개발 기간 1~2주, CHECK API 키 보유, 상용 LLM API 사용 가능

## 1. 한 줄 정의

트레이더가 "삼성전자랑 코스피, 최근 한 달 수익률 갭 알려줘"라고 물으면, LLM이 의도를 파악하고 **백엔드가 CHECK API 호출과 계산을 수행**해, 원본 수치·공식·API 명세 링크가 달린 검증 가능한 답변 카드와 엑셀 파일로 돌려주는 대화형 코파일럿.

## 2. 문제 정의

- 트레이더는 Check Expert 단말 화면 밖의 2차 가공 데이터(수익률 갭, 변동성 비교, 괴리율 등)가 수시로 필요하다.
- CHECK API로 직접 뽑을 수 있지만 API 명세 파악과 연산 구현에 개발 지식이 필요하다.
- 결과적으로 엑셀 수작업이나 IT 부서 의존으로 시간이 지연된다.

## 3. 타겟 사용자

- 1차: 개발 지식 없이 CHECK API 데이터를 활용하려는 트레이더, 펀드매니저, RA.
- 2차(B2B): MTS/HTS에 AI 비서를 도입하려는 증권사.

## 4. 수익 모델 (로드맵)

- B2B API 게이트웨이 종량제 과금.
- White-label 위젯 연 단위 라이선스.
- 지표 카탈로그의 MCP 서버 노출 — 증권사가 자사 AI 비서에 CHECK 지표 tool을 꽂아 쓰는 형태. (MVP는 앱 내부 tool calling만, MCP는 로드맵)

## 5. 핵심 설계 원칙

1. **계산 환각 원천 차단**: 모든 수치 계산은 LLM이 아닌 백엔드 Java 코드가 수행한다. 답변 카드의 수치·차트·근거 패널은 LLM 텍스트가 아니라 백엔드 JSON을 프론트가 직접 렌더한다. LLM은 tool 선택·파라미터 추출·해설 텍스트만 담당한다.
2. **재현 가능한 근거 공개**: 모든 지표 답변에 호출한 CHECK API(명세 문서 링크 포함), 원본 수치, 적용 공식, 중간 계산값을 공개해 트레이더가 엑셀로 직접 검증할 수 있게 한다.
3. **거절 대신 가이드**: 카탈로그 밖 질문은 거절하지 않고 "어떤 CHECK API를 어떻게 조합해 계산하면 되는지" 레시피로 답한다. 사용자가 구현 방법을 명시적으로 요청해도 같은 가이드를 제공한다.
4. **컴플라이언스 바이 디자인**: 투자 판단·권유·전망을 생성하지 않는 팩트 기반 정보 제공으로 한정한다.

## 6. MVP 범위 (1~2주)

**포함**:
- 채팅형 웹앱 (단일 화면): 자연어 질문 → 지표 답변 카드 / 가이드 카드 / 되묻기
- 지표 카탈로그 6종 (아래 7절)
- 근거 패널: 호출 API + 명세 링크, 원본 수치, 공식, 중간 계산값
- xlsx 내보내기 (결과 요약 / 원본 데이터 / 계산 과정 3시트)
- tool 선택 평가셋 기반 "의도 인식 정확도 %" 측정 (발표용 정량 지표)

**제외 (로드맵으로만 언급)**:
- MCP 서버 노출, White-label 위젯, 과금·계정·권한
- 차트 이미지(PNG) 내보내기
- 사용자 정의 지표 등록 (가이드 카드의 "카탈로그 추가 요청" 버튼은 기록만)

## 7. 지표 카탈로그 (6종)

| # | 지표 | 질문 예시 | 계산 |
|---|---|---|---|
| 1 | 수익률 갭 | "삼성전자랑 코스피, 최근 한 달 수익률 갭" | 두 대상(종목/지수)의 기간 수익률 차이 |
| 2 | 변동성 비교 | "에코프로랑 에코프로비엠 변동성 비교" | 일간수익률 표준편차, 연율화 |
| 3 | 괴리율 | "TIGER 미국S&P500 괴리율" | ETF 시장가 vs NAV(iNAV) |
| 4 | 이동평균 이격도 | "카카오 20일선 이격도" | 현재가 / N일 이동평균 − 1 |
| 5 | 상대수익률 랭킹 | "에코프로, 엘앤에프, 포스코퓨처엠 3개월 수익률 순위" | 사용자가 나열한 복수 종목의 기간 수익률 정렬. 테마·업종명("2차전지 종목들")의 종목 목록 자동 확장은 로드맵 |
| 6 | 기간 시세 요약 | "현대차 올해 최고가·최저가·수익률" | 기간 OHLC 집계 |

선정 기준: CHECK API 시세·NAV 데이터만으로 계산 가능(외부 의존 없음), 트레이더가 엑셀로 자주 만드는 항목, 공식이 명확해 근거 패널로 재현 가능.

각 지표는 독립된 실행기 클래스 하나로 구현한다 — 지표 추가 = 클래스 추가. 여기에 가이드 모드용 `explainRecipe` tool을 더해 tool 전체 목록이 된다.

## 8. 아키텍처

접근 방식: **LLM tool calling** (Claude API / Spring AI). 카탈로그의 각 지표를 tool로 정의하고, 파라미터가 모호하면 LLM이 자연스럽게 되묻는다. 범용 NL2API(임의 질문 → 임의 API 조합)는 검증·정확성 보장이 어려워 배제했다.

```
[React SPA]  채팅 UI · 답변 카드(수치/차트/근거 패널) · xlsx 다운로드
     │  REST + SSE(해설 텍스트 스트리밍)
     ▼
[Spring Boot 백엔드]
  chat 모듈      ── 대화 세션, Claude tool calling 루프 (Spring AI)
  catalog 모듈   ── 지표 실행기 6종: CHECK API 호출 + Java 계산 + 근거 생성
  guide 모듈     ── 명세 인덱스(API명·요약·파라미터·문서 URL) 기반 레시피 생성
                    트리거 ①: 어떤 지표 tool도 매칭 안 될 때 (폴백)
                    트리거 ②: 사용자가 구현 방법을 명시적으로 요청할 때 (explainRecipe)
  checkapi 모듈  ── CHECK API 클라이언트, 종목 마스터(이름→코드) 검색, 응답 캐시
  export 모듈    ── Apache POI로 xlsx 생성
     │
     ▼
[PostgreSQL]  종목 마스터, CHECK API 응답 캐시, 대화·tool 호출 로그
```

### 데이터 흐름

1. 사용자 질문 → chat 모듈이 카탈로그 tool 스키마와 함께 Claude에 전달.
2. Claude가 tool 선택 + 파라미터 추출. 종목명은 tool 실행 시 종목 마스터에서 검색하고, 후보가 여러 개면 목록을 Claude에 반환해 되묻게 한다.
3. 지표 실행기: CHECK API 호출 → Java 계산 → `{결과 수치, 시계열, 근거(호출 API·명세 링크·원본 수치·공식·중간값)}` JSON 반환.
4. Claude는 이 JSON 기반으로 해설 텍스트만 생성. 카드 수치는 백엔드 JSON 직접 렌더.
5. tool 미매칭 또는 구현 방법 요청 → guide 모듈이 레시피 답변 생성.

## 9. 화면·UX (단일 채팅 화면)

메시지 스트림에 세 가지 유형이 흐른다:

1. **일반 대화 메시지** — 질문, 해설(SSE 스트리밍), 되묻기. 종목 되묻기에는 후보 종목 칩 버튼을 렌더해 클릭 한 번으로 선택.
2. **지표 답변 카드** — 헤더(지표·대상·기간) / 핵심 수치 / 차트(Recharts, 지표별 기본 1종) / 근거 패널(접이식: 호출 API+명세 링크 → 원본 수치 표 → 공식 → 중간 계산값) / 액션 바(xlsx 다운로드).
   - xlsx 구성: 시트1 결과 요약, 시트2 API 원본 데이터, 시트3 공식·계산 과정.
3. **가이드(레시피) 카드** — 필요 CHECK API 목록(각 명세 링크) → 호출 파라미터 → 조합 공식 → 예시 요청/응답. 하단 "카탈로그 추가 요청" 버튼(MVP는 기록만).

카드 컴포넌트는 지표 공통 스키마 1종으로 통일해 지표별 프론트 작업을 제거한다.

화면 하단 고지 문구 고정: "본 자료는 AI가 시장 데이터 기반으로 생성한 정보성 자료이며 투자권유가 아닙니다."

## 10. 에러 처리와 가드레일

**외부 의존성 장애**
- CHECK API 실패: 지수 백오프 재시도 → DB 캐시 폴백. 데모 종목 풀은 사전 수집.
- LLM 장애·타임아웃: 에러 메시지 + 재시도 버튼. 진행 중 tool 결과는 폐기.

**입력·파라미터 오류** — 원칙: 실행기는 검증하고, 되묻기는 LLM에 맡긴다.
- 종목 다건 매칭 → 후보 목록 반환 → 칩 되묻기. 0건 → 유사 후보와 함께 안내.
- 파라미터 검증 실패(기간 역전, ETF 전용 지표에 일반 주식, 상장일 이전 기간 등) → 실행기가 구조화 에러를 Claude에 반환 → 자연어 안내·되묻기. 백엔드는 잘못된 계산 결과를 절대 내지 않는다.
- 데이터 부족 → 계산 가능 범위를 명시한 부분 결과 또는 명시적 안내.

**컴플라이언스 가드레일**
- 투자 판단 요청("사야 돼?") → 시스템 프롬프트로 투자 권유·전망 생성 금지, 정보성 답변으로 전환.
- 카드 수치의 백엔드 직접 렌더 자체가 최종 방어선 — LLM 해설이 수치를 잘못 말해도 카드가 정답을 보여준다.

**관측성**
- 모든 대화·tool 호출·에러를 DB에 로깅 (디버깅 + 평가셋 원천 데이터).

## 11. 테스트

1. **지표 계산 단위 테스트**: 실행기 6종에 고정 픽스처(사전 수집 CHECK API 응답) 투입 → 엑셀로 별도 계산한 기대값과 대조. 최우선 투자 대상.
2. **tool 선택 평가셋**: 실전형 질문 30~50개(정답 tool·파라미터 라벨링) 배치 실행 → "의도 인식 정확도 %" 산출. 모호 질문(정답=되묻기), 카탈로그 밖 질문(정답=가이드), 투자 판단 질문(정답=거절)을 포함.
3. **xlsx 검증**: 다운로드 파일 수치와 답변 카드 수치 일치 스냅샷 테스트.
4. **E2E 데모 리허설**: 데모 시나리오 전체를 캐시 데이터로 리허설.

## 12. 데모 시나리오 (발표 3분)

1. 문제 제기: "트레이더의 2차 가공 데이터 수요 → 엑셀 수작업/IT 의존" 슬라이드.
2. 질문 ① "삼성전자랑 코스피, 최근 한 달 수익률 갭" → 카드·차트 → 근거 패널 펼쳐 API 링크·원본 수치·공식 시연.
3. 질문 ② 모호한 종목명 → 칩 되묻기 → 클릭 한 번에 답변.
4. 질문 ③ 카탈로그 밖 지표 → 가이드 카드 (거절 대신 레시피 + 명세 링크).
5. xlsx 다운로드해 열기: "엑셀 수작업이 이 버튼 하나".
6. 정량 지표(의도 인식 정확도) 제시 → 로드맵: MCP 서버, White-label 위젯, 카탈로그 확장.
