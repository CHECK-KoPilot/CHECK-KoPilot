# CHECK API 엔드포인트 조사 결과

- 조사일: 2026-07-22
- 출처: `https://checkapi.koscom.co.kr/index.html` 의 SPA 번들 `/js/main.js`
  (`/intro/introhome` 은 `location.href='/index.html'` 리다이렉트만 있는 셸이라 HTML에는 내용이 없다)
- Base URL: `https://checkapi.koscom.co.kr`
- 인증: 모든 엔드포인트가 `cust_id`(CHECK 단말 고객번호 10자리) + `auth_key`(API 인증키)를 요구.
  본 프로젝트 값은 Notion `Koscom 프로젝트` 페이지 참조 — 코드에는 환경변수로만 주입한다.

| **`apis_full.json`** | API 776건 × {제목, 파라미터(이름·필수여부), 반환 F코드 목록} |

### F코드는 전역 사전이다

F코드의 의미는 **API와 무관하게 전역적으로 동일**하다. `F15001`은 어디서나 현재가, `F16013`은 어디서나 단축코드다.
전체 24,648개 필드 슬롯이 1,841개 고유 코드로 수렴한다. 의미가 갈리는 코드는 5.7%뿐이고
그마저 `단축코드`/`종목코드`처럼 표기 차이다.

따라서 **API별로 필드 설명을 저장하지 말고, 전역 F코드 사전 1개 + API별 코드 목록**으로 관리한다
(전량 인라인 334KB → 사전 46KB + 코드 목록).

### `detail` 필드에 진짜 의미가 있다

투자자별 지표는 `desc`가 인덱스만 담고 있어 그것만으로는 쓸 수 없다. **`detail`에 실제 구분이 들어 있다.**

```
F06505_11  desc="종목투자자별매도거래량11"   detail="외국인"
F06508_11  desc="종목투자자별순매수거래량11"  detail="외국인"
```

투자자 인덱스: 1 금융투자 · 2 보험 · 3 투신 · 4 은행 · 5 기타금융 · 6 연금 · 7 미분류 · 8 **기관계**
· 9 기타법인 · 10 **개인** · 11 **외국인** · 12 종합계

전체 필드의 43.3%가 `detail`을 갖는다. `fcodes.json`은 `desc(detail)` 형태로 병합해 저장했다.
`detail`은 코드값 설명도 담는다(예: `F18070` 시장조치 = 00 정상 / 10 시초가산출 / 20 투자주의 / …).

문서 페이지 URL 형식: `https://checkapi.koscom.co.kr/<카테고리>/<rpath>`
예: `https://checkapi.koscom.co.kr/stock/m003code`, `https://checkapi.koscom.co.kr/future/m005intra`
호출 경로와 달리 모듈과 접미사 사이에 슬래시가 없다 — 호출 `/stock/m001/hist_info` ↔ 문서 `/stock/m001hist`.

## 지표 카탈로그 6종에 필요한 엔드포인트

`POST /stock/m001/hist_info` **하나로 지표 1·2·3·4·6이 모두 커버된다.** (호출 규약은 아래 「호출 규약」 절 참조)

### `/stock/m001/hist_info` — 거래소 종목 일별정보

요청: `cust_id`, `auth_key`, `jcode`(단축코드 6자리), `sdate`/`edate`(YYYYMMDD), `data_list`(선택, 미지정 시 전체)

주요 응답 필드(총 23개):

| 필드 | 타입 | 의미 | 용도 |
|---|---|---|---|
| `F12506` | INT | 입회일 | 시계열 키 |
| `F15001` | INT | 현재가(종가) | 수익률·이격도·변동성 |
| `F15009` / `F15010` / `F15011` | INT | 시가 / 고가 / 저가 | 기간 OHLC 요약 |
| `F15004` | DECIMAL(12,2) | 등락율 | 일간수익률 검증 |
| `F15015` / `F15023` | INT | 거래량 / 거래대금 | 요약 카드 |
| `F15028` | INT | 시가총액 | 참고 |
| **`F15301`** | DECIMAL(12,2) | **ETP지표가치(NAV/IV)** | **ETF 괴리율** |

`F15301`이 일별 시계열에 포함되므로 ETF 괴리율도 별도 NAV API 없이 같은 호출로 계산할 수 있다.
(장중 실시간 괴리율이 필요하면 `/stock/m001/intra_info` — NAV와 괴리율 필드를 직접 제공)

### `/stock/m002/hist_info` — 거래소 업종(지수) 일별정보

요청: `jcode`가 업종코드(코스피=`1`), 나머지는 동일. 응답에 `F15001` 현재가·`F15009~11` OHLC 포함.
**"삼성전자 vs 코스피 수익률 갭"의 코스피 쪽이 이 엔드포인트.** 코스닥 지수는 `/stock/m004/hist_info`.

### 복수 종목 최적화

지표 5(상대수익률 랭킹)는 종목마다 `hist_info`를 호출한다. 종목 수가 많아지면
`/stock/m001/hist_info_port`(`codelist` + `edate`)로 일괄 조회할 수 있으나, `sdate`가 없어
기간 조회에는 쓸 수 없다 — MVP는 종목별 순차 호출 + Redis 캐시로 간다.

## 가이드 모듈용 명세 인덱스

`specs.json`이 곧 가이드 모듈(`api-spec-index.yaml`)의 원천 데이터다.
776건 전체를 LLM 컨텍스트에 넣을 수는 없으므로 계획대로 2단계 조회를 유지한다:
`explain_recipe`가 한 줄 요약 카탈로그를 반환 → `get_api_spec`이 apiId별 상세(파라미터·응답 필드)를 반환.

## 에러 규약 (번들 명세 기준 — 실제 동작은 아래 「호출 규약」이 우선)

번들 문서는 아래 형태를 적고 있으나, 실호출에서는 `message`가 객체가 아닌 **한국어 문자열**로 왔고 `jcode_denied`는 발생하지 않았다.

```json
{"success": false, "message": {"errmsg": "access_denied", "desc": "User denied access"}}
```

## 호출 규약 (2026-07-22 실호출로 확정)

**POST 전용.** GET은 파라미터가 맞아도 항상 인증 실패로 거부된다.

```bash
curl -X POST https://checkapi.koscom.co.kr/stock/m001/hist_info \
  -H 'Content-Type: application/json' \
  -d '{"cust_id":"...","auth_key":"...","jcode":"005930","sdate":"20260701","edate":"20260710"}'
```

body는 `application/json`과 `application/x-www-form-urlencoded` 둘 다 동작한다.
**인증정보는 헤더가 아니라 payload에 넣는다.**

**`data_list`로 필요한 필드만 받는다.** 생략하면 전체 Data Set이 온다(`hist_info`는 23개 필드).
콤마 구분이고 공백을 허용하며 **요청한 순서대로** 반환된다.

```json
{"cust_id":"...","auth_key":"...","jcode":"005930","sdate":"20260720","edate":"20260722",
 "data_list":"F12506, F15001, F15009, F15010, F15011, F15301"}
```

지표 실행기는 필요한 F코드만 명시해 페이로드를 줄인다.

**응답 봉투**

| 상황 | 응답 |
|---|---|
| 성공 | `{"success":true,"results":[...]}` |
| 인증 실패 | `{"success":false,"message":"cust_id 또는 auth_key가 정확하지 않습니다."}` |
| **존재하지 않는 종목코드** | **`{"success":true,"results":[]}`** — 에러가 아니다 |

HTTP status는 실패 시에도 **항상 200**이다. 반드시 `success` 필드로 판정하고, `success:true`라도 `results`가 비어 있으면 종목 없음/데이터 없음으로 처리해야 한다. 번들 명세에 적힌 `jcode_denied` 에러는 `hist_info`에서 실제로 발생하지 않았다.

**응답 형식 주의**

- 시계열은 **최신 → 과거 내림차순**이다. 수익률 계산 시 정렬 방향을 반드시 뒤집거나 명시적으로 처리할 것.
- 수치가 **문자열로 온다** (`"F15001":"285000"`, `"F15004":"2.52"`). 일부만 정수(`F12506`, `F15006`, 지수의 `F16013`). 파싱 시 `BigDecimal(String)` 사용.
- `F12506`(입회일)은 `20260710` 형태의 정수.

**조회 기간·레이트**

- 1년 7개월(20250102~20260722) 조회에서 377행이 한 번에 반환됐다. 실질적 기간 상한은 확인되지 않았다.
- 연속 10회 호출이 약 1.1초에 완료됐다. 레이트리밋에 걸리지 않았다.

## ETF NAV 검증

`F15301`(ETP지표가치 NAV/IV)은 **ETF에서만 유효**하다.

- 삼성전자(005930): `"F15301":"0.00"`
- KODEX 200(069500): `"F15301":"130791.06"` (종가 `F15001`=131010 → 괴리율 +0.17%)

ETF 종목 목록은 `/stock/m001/code_etf_info`로 1150건이 조회된다(`F34501`="EF").
